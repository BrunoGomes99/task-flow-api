# ECS Delivery Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** After the platform plan is merged, make GitHub Actions deploy `github.sha` to the three .NET ECS services and stop a later Terraform apply from rolling that tag back.

**Architecture:** The workflow reads the live task definition, replaces only the application image and `SERVICE_VERSION` (including the ADOT container's copy of that variable), registers a revision, and calls `ecs update-service`. Terraform ignores `container_definitions` on those three task definitions because the image lives inside that JSON string. Redis and RabbitMQ stay owned by Terraform. Design: [../specs/2026-11-04-ecs-migration-design.md](../specs/2026-11-04-ecs-migration-design.md).

**Tech Stack:** GitHub Actions, AWS CLI, `jq`, ECS, Terraform AWS provider `~> 5.0`.

## Global Constraints

- Start this plan only after `feature/ecs-migration` is merged. The cluster and the three services already exist.
- Deploy `taskflow-api`, `taskflow-scheduler`, and `taskflow-notifications` only. Do not deploy Redis or RabbitMQ from CI.
- The running identity is `github.sha`. `:latest` may still be pushed, and it is not what the service runs.
- One approval gate, the existing `production` environment, before publish. `workflow_dispatch` stays.
- The smoke check is `GET /health/ready` on the ALB. Container restart probes stay on `GET /health/live`.
- The OIDC role is operator-owned. This plan documents the policy. It does not create the role in Terraform.
- Changing the ADOT image later requires one apply with the `lifecycle` block removed, then the block goes back. CI copies the ADOT image from the live task definition and does not replace it.

- [x] **Step 2: Add the job**

Append this job to `.github/workflows/ci.yml`. It replaces the deleted `redeploy-ec2` job. `publish-ecr` already outputs `image_tag` and `registry`.

```yaml
  deploy-ecs:
    name: Deploy github.sha to ECS
    needs: publish-ecr
    if: >
      github.event_name == 'workflow_dispatch' ||
      (github.event_name == 'push' && github.ref == 'refs/heads/main')
    runs-on: ubuntu-latest
    permissions:
      contents: read
      id-token: write
    env:
      AWS_REGION: ${{ vars.AWS_REGION }}
      ECS_CLUSTER: ${{ vars.ECS_CLUSTER }}
      API_REPOSITORY: ${{ vars.API_REPOSITORY }}
      SCHEDULER_REPOSITORY: ${{ vars.SCHEDULER_REPOSITORY }}
      NOTIFICATIONS_REPOSITORY: ${{ vars.NOTIFICATIONS_REPOSITORY }}
      IMAGE_TAG: ${{ needs.publish-ecr.outputs.image_tag }}
      REGISTRY: ${{ needs.publish-ecr.outputs.registry }}
      ALB_DNS_NAME: ${{ vars.ALB_DNS_NAME }}
    steps:
      - name: Configure AWS credentials (OIDC)
        uses: aws-actions/configure-aws-credentials@v4
        with:
          role-to-assume: ${{ vars.AWS_ROLE_TO_ASSUME }}
          aws-region: ${{ env.AWS_REGION }}

      - name: Register revisions and update services
        run: |
          set -euo pipefail
          deploy_service() {
            local family="$1"
            local container="$2"
            local image="$3"
            local current
            current="$(aws ecs describe-task-definition --task-definition "$family" --query 'taskDefinition' --output json)"
            local payload
            payload="$(echo "$current" | jq --arg container "$container" --arg image "$image" --arg version "$IMAGE_TAG" '
              .containerDefinitions |= map(
                if .name == $container then
                  .image = $image
                  | .environment |= map(if .name == "SERVICE_VERSION" then .value = $version else . end)
                elif .name == "adot" then
                  .environment |= map(if .name == "SERVICE_VERSION" then .value = $version else . end)
                else
                  .
                end
              )
              | {
                  family,
                  taskRoleArn,
                  executionRoleArn,
                  networkMode,
                  containerDefinitions,
                  volumes,
                  placementConstraints,
                  requiresCompatibilities,
                  cpu,
                  memory,
                  runtimePlatform,
                  pidMode,
                  ipcMode
                }
              | with_entries(select(.value != null))
            ')"
            local arn
            arn="$(aws ecs register-task-definition --cli-input-json "$payload" --query 'taskDefinition.taskDefinitionArn' --output text)"
            aws ecs update-service \
              --cluster "$ECS_CLUSTER" \
              --service "$family" \
              --task-definition "$arn" \
              --query 'service.serviceName' \
              --output text
          }
          deploy_service "${{ vars.ECS_SERVICE_API }}" "taskflow-api" "${REGISTRY}/${API_REPOSITORY}:${IMAGE_TAG}"
          deploy_service "${{ vars.ECS_SERVICE_SCHEDULER }}" "taskflow-scheduler" "${REGISTRY}/${SCHEDULER_REPOSITORY}:${IMAGE_TAG}"
          deploy_service "${{ vars.ECS_SERVICE_NOTIFICATIONS }}" "taskflow-notifications" "${REGISTRY}/${NOTIFICATIONS_REPOSITORY}:${IMAGE_TAG}"
          aws ecs wait services-stable \
            --cluster "$ECS_CLUSTER" \
            --services "${{ vars.ECS_SERVICE_API }}" "${{ vars.ECS_SERVICE_SCHEDULER }}" "${{ vars.ECS_SERVICE_NOTIFICATIONS }}"
          curl -fsS "http://${ALB_DNS_NAME}/health/ready"
          echo "Deploy OK: ${IMAGE_TAG}"
```

Update the workflow header comment so it says publish is followed by `ecs update-service` for the three .NET services.
