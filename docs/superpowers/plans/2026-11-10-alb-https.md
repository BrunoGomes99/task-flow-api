# ALB HTTPS Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Serve the existing API on HTTPS at a subdomain the operator controls, with the ACM certificate on the current ALB.

**Architecture:** TLS ends at the ALB. The target group stays HTTP on port 8080. Port 443 forwards. Port 80 redirects. DNS validation records are outputs; the operator creates them outside Terraform. The deploy smoke check calls `https://<api_domain_name>/health/ready`, because the certificate name is that domain and not the ALB hostname.

**Tech Stack:** Terraform AWS provider, ACM, the existing ALB, GitHub Actions curl.

**Spec:** [../specs/2026-11-10-alb-https-design.md](../specs/2026-11-10-alb-https-design.md)

## Global Constraints

- Start only after `feature/cors` is merged and `api_domain_name` is a real subdomain. Do not use a zone apex.
- `api_domain_name` has no default. Do not accept an empty string as "stay on HTTP".
- Certificate is public ACM, DNS validation, region `var.aws_region`. No Route 53 zone.
- SSL policy is `ELBSecurityPolicy-TLS13-1-2-2021-06`.
- Listener 443 forwards to the existing target group. Listener 80 returns `HTTP_301` to HTTPS on 443.
- Target group protocol, port 8080, and health check `GET /health/ready` matcher `200` stay as they are.
- Ingress 443 uses `allowed_api_cidr`. Ingress 80 stays, so the redirect is reachable. API ingress remains 8080 from the ALB security group only.
- Do not set `ASPNETCORE_HTTPS_PORT` or `ASPNETCORE_HTTPS_PORTS`. Do not remove `UseHttpsRedirection`.
- Do not change CORS code. A Pages origin is `cors_allowed_origins` in gitignored tfvars.
- Smoke check URL is `https://${API_DOMAIN_NAME}/health/ready`. Do not curl the raw ALB hostname over TLS.
- Workers, Redis, and RabbitMQ gain no public ingress.

- [ ] **Step 1: Require the domain name**

In `infra/variables.tf`:

```hcl
variable "api_domain_name" {
  description = "Public subdomain for the API, such as api.example.com. ACM validates this name. Not a zone apex."
  type        = string

  validation {
    condition     = can(regex("^[a-z0-9-]+(\\.[a-z0-9-]+){2,}$", var.api_domain_name))
    error_message = "api_domain_name must be a lowercase subdomain with at least two dots, such as api.example.com, and must not be a URL."
  }
}
```

Pass `api_domain_name = var.api_domain_name` into `module "ecs"` in `infra/main.tf`.

In `infra/modules/ecs/variables.tf`:

In `infra/terraform.tfvars.example`, add a commented line, not a live example.com value that an apply would try to validate:

- [ ] **Step 2: Create the certificate and the validation wait**

`infra/modules/ecs/acm.tf`:

```hcl
resource "aws_acm_certificate" "api" {
  domain_name       = var.api_domain_name
  validation_method = "DNS"

  lifecycle {
    create_before_destroy = true
  }
}

resource "aws_acm_certificate_validation" "api" {
  certificate_arn         = aws_acm_certificate.api.arn
  validation_record_fqdns = [for record in aws_acm_certificate.api.domain_validation_options : record.resource_record_name]
}
```

In `infra/modules/ecs/outputs.tf`:

```hcl
output "acm_validation_records" {
  value = [
    for record in aws_acm_certificate.api.domain_validation_options : {
      name  = record.resource_record_name
      type  = record.resource_record_type
      value = record.resource_record_value
    }
  ]
}

output "api_domain_name" {
  value = var.api_domain_name
}
```

In `infra/outputs.tf`:

```hcl
output "acm_validation_records" {
  description = "CNAMEs to create at the DNS host before certificate validation can finish."
  value       = module.ecs.acm_validation_records
}

output "api_domain_name" {
  description = "Public API hostname. Point a CNAME at alb_dns_name."
  value       = module.ecs.api_domain_name
}
```

- [ ] **Step 3: Open 443 on the ALB security group**

In `infra/modules/security/main.tf`, next to `alb_http`:

```hcl
resource "aws_vpc_security_group_ingress_rule" "alb_https" {
  security_group_id = aws_security_group.alb.id

  cidr_ipv4         = var.allowed_api_cidr

```

Keep the port 80 rule. In `infra/variables.tf`, change the `allowed_api_cidr` description so it says the CIDR may reach the API load balancer on TCP 80 and TCP 443.

### Task 2: Listeners, health URL, and the deploy curl

**Files:**

**Interfaces:**
- Consumes: `aws_acm_certificate_validation.api.certificate_arn`
- Produces: `aws_lb_listener.https` on 443, and `aws_lb_listener.http` as a redirect

- [ ] **Step 1: Add the HTTPS listener and redirect port 80**

Replace the default action of `aws_lb_listener.http` in `infra/modules/ecs/alb.tf`. The resource name stays `http`.

```hcl
resource "aws_lb_listener" "http" {
  load_balancer_arn = aws_lb.api.arn
  port              = 80
  protocol          = "HTTP"

  default_action {
    type = "redirect"

    redirect {
      port        = "443"
      protocol    = "HTTPS"
      status_code = "HTTP_301"
    }
  }
}

resource "aws_lb_listener" "https" {
  load_balancer_arn = aws_lb.api.arn
  port              = 443
  protocol          = "HTTPS"
  ssl_policy        = "ELBSecurityPolicy-TLS13-1-2-2021-06"
  certificate_arn   = aws_acm_certificate_validation.api.certificate_arn

  default_action {
    type             = "forward"
    target_group_arn = aws_lb_target_group.api.arn
  }
}
```

Leave `aws_lb_target_group.api` unchanged: protocol `HTTP`, port `8080`, health check path `/health/ready`, matcher `200`.

In `infra/modules/ecs/services.tf`, extend the API service `depends_on`:

```hcl
depends_on = [aws_ecs_service.redis, aws_lb_listener.http, aws_lb_listener.https]
```
